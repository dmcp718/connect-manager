## Bugs surfaced (13)

Every one of these required a fix-and-resume turn during the smoke. None were
caught by the dress rehearsal against ministack (`local/terraform-dress-rehearsal.md`)
because LocalStack accepts these shapes that real AWS rejects. Several would
have been caught by a stricter pre-commit hook on terraform-fmt + a non-ASCII
audit of resource description fields, and by `terraform plan` against a real
AWS account (no apply needed).

### 1. Non-ASCII em-dashes in EC2 security-group descriptions

EC2 `CreateSecurityGroup` rejects `—` (em-dash) and `→` (right arrow):

> InvalidParameterValue: Value (...) for parameter GroupDescription is invalid. Character sets beyond ASCII are not supported.

Hit at `terraform/main.tf:189` (worker_tasks SG) and
`terraform/modules/alb/main.tf:9` (alb SG). Fixed: replaced with `--` and `to`.

### 2. Apostrophe in EC2 SG description

EC2 only accepts `a-zA-Z0-9. _-:/()#,@[]+=&;{}!$*` in `GroupDescription`. The
worker_tasks SG read "workers don't accept inbound" — the `'` is rejected:

> InvalidParameterValue: Invalid security group description.

Fix: rephrase to no apostrophe.

### 3. Non-printable / non-ASCII in RDS parameter group description

`aws_db_parameter_group.description` rejected the em-dash too:

> InvalidParameterValue: The parameter Description must not contain non-printable control characters.

(AWS misclassifies `—` as a control character here.) Fixed at
`terraform/modules/rds/main.tf:30`.

### 4. Apostrophe in CloudWatch alarm_description

`alarm_description` for the `worker_queue_depth_high` alarm read "(KEDA isn't keeping up)" — same apostrophe class. Hit late because alarms create
after the SGs. Fix: rephrase.

### 5. Fargate task CPU/memory not a valid pairing

`module.ecs_service_web.aws_ecs_task_definition.web` summed `var.web_cpu`
(512) + `var.lucidlink_api_cpu` (256) = 768 task CPU, paired with 1536
memory. Fargate rejects:

> ClientException: No Fargate configuration exists for given values: 768 CPU, 1536 memory.

Valid pairings start at 256/512 and step through documented combos
(256/{512,1024,2048}, 512/{1024..4096}, 1024/{2048..8192}, ...). Fix: bumped
`web_cpu` default to 768 and `web_memory` default to 1536, so the sums are
1024/2048 — a valid pairing.

### 6. RDS engine_version 16.4 retired

> InvalidParameterCombination: Cannot find version 16.4 for postgres.

Fix: bumped default to 16.13 (current available, verified via
`aws rds describe-db-engine-versions --engine postgres --engine-version 16
--query 'DBEngineVersions[?Status==\`available\`].EngineVersion'`).

### 7. RDS db_name "connect" is a Postgres reserved word

> InvalidParameterValue: DBName connect cannot be used. It is a reserved word for this engine.

Fix: renamed `db_name` default to `connectdb`, and the master `username`
default from `connect` to `connectadmin` (same reserved-word risk class).

### 8. Migrate task workingDirectory not set; alembic can't find scripts

`scripts/deploy.sh` registered the migrate task definition with command
`alembic -c /migrations/alembic.ini upgrade head` but no `workingDirectory`,
so cwd defaulted to /app. `alembic.ini` has `script_location = alembic`
(relative); from cwd=/app there's no `alembic/` subdir.

> FAILED: Path doesn't exist: alembic. Please use the 'init' command to create a new scripts folder.

Fix: `terraform/modules/ecs-task-migrate/main.tf` now sets
`workingDirectory = "/migrations"` and `PYTHONPATH=/app` on the migrate
container so `alembic env.py`'s `from db.models import Base` resolves.

### 9. configparser % interpolation crash on RDS-generated password

`alembic/env.py` did `config.set_main_option("sqlalchemy.url", DATABASE_URL)`.
RDS-generated passwords routinely contain `%`, which configparser's
BasicInterpolation reads as `%(varname)s` and crashes:

> ValueError: invalid interpolation syntax in '...X{c?KefFk3u:0$%fL+3CUwRiUcSc38r+@...' at position 48

Fix: escape `%` -> `%%` before passing to set_main_option.

### 10. Alembic ran asyncpg in sync context

After fix 9, alembic still failed because `DATABASE_URL` uses
`postgresql+asyncpg://` (the runtime driver) but alembic runs migrations
synchronously:

> sqlalchemy.exc.MissingGreenlet: greenlet_spawn has not been called; can't call await_only() here.

Fix: in `alembic/env.py`, swap `postgresql+asyncpg://` to
`postgresql+psycopg://` (sync) for migrations only. The web/worker apps
keep asyncpg for their request path.

### 11. JWT_SECRET_KEY valueFrom ARN format

`terraform/main.tf:69` had `"${module.secrets.secret_arns["jwt"]}::"` which
produces `arn:...:jwt-zMZ95m::` — only two trailing colons (so two empty
segments). ECS expects exactly three trailing segments
(`<json-key>:<version-stage>:<version-id>`). All three must be present even
if empty:

> ResourceInitializationError: ... unexpected ARN format with parameters when trying to retrieve ASM secret.

The JWT secret is JSON `{"value":"<hex>"}` (per the bootstrap TUI's seeder
contract), so the right form is `:value::` to extract the `value` key. Fix:
`"${module.secrets.secret_arns["jwt"]}:value::"`.

### 12. scripts/deploy.sh didn't export AWS_DEFAULT_REGION

The script set `REGION="${AWS_REGION:-us-east-1}"` as a script-local variable
but didn't export it. `aws` CLI calls in the script honored
`~/.aws/config`'s default region (us-west-2 here, not the deployed
us-east-1) — every call returned "Unable to describe task definition" and
similar 404s.

Fix: `export AWS_DEFAULT_REGION="$REGION"` and `export AWS_REGION="$REGION"`
at script entry.

### 13. Worker crashloops on RDS TLS cert verification

After fix 12 made web tasks pull images successfully, worker logs showed:

> ssl.SSLCertVerificationError: [SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed: self-signed certificate in certificate chain

RDS uses the AWS RDS CA (`rds-ca-rsa2048-g1`) signed by AWS Trust Services'
roots, which aren't in the default Linux CA bundle in `python:3.12-slim`.
The RDS parameter group sets `rds.force_ssl=1` so we can't disable TLS
entirely.

Fix: extended `app/services/database.py:_build_ssl_arg` to honor a new env
var `DATABASE_URL_INSECURE_SSL=1` — when set, TLS is still negotiated but
cert chain validation is disabled (`ctx.check_hostname=False`,
`ctx.verify_mode=ssl.CERT_NONE`). Set on web/worker/migrate via
`terraform/main.tf`'s `app_env_vars`. Acceptable because the network path
between Fargate and RDS is private (VPC-internal); no MITM exposure.

A future hardening pass would bake the AWS RDS CA bundle into the image
and flip `DATABASE_URL_INSECURE_SSL` back to `0`.

### 14. lucidlink-api healthcheck used bash-only `/dev/tcp/` redirection

The healthcheck command in `terraform/modules/ecs-service-web/main.tf`
was `["CMD-SHELL", "exec 3<>/dev/tcp/127.0.0.1/3003 && echo > /dev/null"]`.
`/dev/tcp/...` is a bash-builtin pseudo-device — not present in dash, ash,
busybox sh. The lucidlink-api Nest.js image's `sh` doesn't support it, so
the healthcheck always failed → container went UNHEALTHY → web container
(which had `dependsOn { condition = "HEALTHY" }`) never started → ALB
target group had zero healthy targets → 502s.

Fix: use Node (always present in the Nest.js image) to GET the root and
exit 0 if the status code is < 500. Also relaxed `dependsOn.condition` to
`"START"` — web does its own retries and waiting for HEALTHY adds 30s+ of
startup latency without preventing the rare transient connection during
the sidecar's own warm-up.

### 15. main.py `_startup` called `ensure_admin_exists()` without session

`services/auth.py:ensure_admin_exists` is `async def` and takes a session
parameter. main.py's lifespan handler was calling it sync without args:

> TypeError: ensure_admin_exists() missing 1 required positional argument: 'session'

This was an awsk-opc TODO that hadn't been wired. The fix opens a session
via the configured sessionmaker and awaits ensure_admin_exists inside.
